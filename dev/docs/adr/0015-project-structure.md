# ADR-0015: プロジェクト構成 (src layout)

- 日付: 2025-11-22
- ステータス: 承認
- レイヤ: dev-experience
- 種別: ディレクトリ構成
- 関連コンポーネント: src/

---

## 1. 背景 / コンテキスト

Python プロジェクトのディレクトリ構成には、フラットレイアウト（ルートにパッケージを置く）と src レイアウト（`src/` 配下に置く）の2つの主流があります。

---

## 2. 決定

**src layout** を採用します。

```text
kamojiros/
├── src/
│   └── kamojiros/
│       ├── core/
│       ├── infrastructure/
│       ├── apps/
│       └── ...
├── tests/
├── pyproject.toml
└── ...
```

---

## 3. 選択肢と評価

### 採用案 (src layout)

- メリット:
  - **インポートエラー防止**: 開発中のディレクトリで `import kamojiros` した際に、インストールされたパッケージではなくカレントディレクトリのフォルダを誤って読み込む事故を防げる。
  - **明示性**: ソースコードと設定ファイル・テストコードが明確に分離される。
- デメリット:
  - 編集可能なインストール（`pip install -e .`）が必要になる（開発時は必須）。

### 代替案 A (Flat layout)

- 概要: ルートに `kamojiros/` を置く。
- 採用しなかった理由:
  - テスト実行時などにパスの問題が起きやすい。

---

## 4. 根拠（評価軸と判断）

- **Best Practice**: 現代の Python パッケージングのベストプラクティスに従うため。
- **Reliability**: テスト環境と本番環境の差異を減らすため。

---

## 5. 影響範囲

- **Build**: ビルドツール（hatchling, setuptools 等）の設定で `src` を指定する必要がある（`pyproject.toml` で自動検出されることが多い）。
