# ADR-0008: 興味プロファイル管理（スナップショット方式）

- 日付: 2025-11-22
- ステータス: 提案中
- レイヤ: core / data
- 種別: データストア
- 関連コンポーネント: apps.theme_generator

---

## 1. 背景 / コンテキスト

エージェントがユーザーにとって「今、面白い」テーマを提案するためには、ユーザーの興味（Interest）をモデル化し、追跡する必要があります。
興味は時間とともに変化するため、その推移も記録したいと考えています。

- 目的・解決したいこと:
  - 「今」の興味の重み付けを知りたい。
  - 過去にどういう興味を持っていたかの履歴を残したい。
  - 複雑な DB スキーマを避け、まずは手軽に始めたい。

---

## 2. 決定

興味プロファイルは **YAML ファイルによるスナップショット** として管理します。
`data/interests/YYYY-MM-DD.yaml` のように日付ごとにファイルを保存し、最新のファイルを「現在の興味」として扱います。

---

## 3. 選択肢と評価

### 採用案（YAML スナップショット）

- 概要:
  - 日付、興味タグ、重み（0.0-1.0）、メモを含む YAML ファイルを保存。
  - 履歴はファイルシステム上の別ファイルとして残る。
- メリット:
  - **シンプル**: DB が不要。テキストエディタで人間が手動調整しやすい。
  - **履歴管理**: Git で管理すれば差分も見える。
  - **可読性**: 構造が直感的。
- デメリット:
  - クエリ（「特定のタグの興味推移」など）が難しい。ファイルを全部パースする必要がある。

### 代替案 A (RDB テーブル)

- 概要: `interests` テーブルと `interest_history` テーブルを作る。
- 採用しなかった理由:
  - まだ「どんなパラメータが必要か」が固まっていないため、スキーマ変更が頻発しそう。
  - 初期フェーズではオーバーエンジニアリング。

---

## 4. 根拠（評価軸と判断）

- **Small Start**: まだ仕様が固まりきっていない概念（Interest）なので、最も変更に強く、捨てやすい実装を選びました。
- **Human-in-the-loop**: 興味の重み付けは、エージェントの自動推定だけでなく、人間が手で修正したい場面が多いと予想されます。YAML なら手動編集が容易です。

---

## 5. 影響範囲

- **Data**: `data/interests/` ディレクトリを作成。
- **Apps**: `ThemeGenerator` は最新の YAML を読み込んで動作する。

---

## 6. ロールアウト / 移行方針

- フェーズ4（予定）:
  - 最初の `data/interests/YYYY-MM-DD.yaml` を手動作成する。
  - `ThemeGenerator` に読み込みロジックを実装する。
- フェーズ5以降:
  - エージェントが自動で「翌日の興味プロファイル」を生成・提案するフローを作る。

---

## 7. オープンな論点 / フォローアップ

- **パラメータ設計**: `weight` (0-1) だけで十分か？ `velocity`（飽きつつある/ハマりだした）や `category` などが必要になるかもしれない。YAML ならフィールド追加は容易。
