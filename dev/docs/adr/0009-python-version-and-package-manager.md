# ADR-0009: Python バージョンとパッケージ管理 (Python 3.14 + uv)

- 日付: 2025-11-22
- ステータス: 承認
- レイヤ: infrastructure / dev-experience
- 種別: 言語・ツール選定
- 関連コンポーネント: pyproject.toml, noxfile.py

---

## 1. 背景 / コンテキスト

Kamojiros は個人的な実験プロジェクトであり、最新の Python 機能（特に型システムや非同期処理）を積極的に試したいと考えています。
また、依存関係の解決や仮想環境の管理を高速かつ確実に行う必要があります。

- 目的・解決したいこと:
  - 最新の言語機能（PEP 649 遅延評価など）を使いたい。
  - パッケージインストールやロックファイルの同期を高速化したい。

---

## 2. 決定

- **Python Version**: **3.14 (preview)** または **3.13** を採用します。
  - 3.14 は実験的な機能（annotation の遅延評価など）を試すために使用。
  - 3.13 は安定版としてのベースライン。
- **Package Manager**: **uv** を採用します。
  - `pip` + `venv` や `poetry` の代わりに、高速な `uv` を使用して依存関係管理と仮想環境作成を行います。

---

## 3. 選択肢と評価

### 採用案 (Python 3.14 + uv)

- メリット:
  - **uv**: Rust 製で爆速。`pip-tools` 互換のワークフローも可能だが、`uv sync` / `uv lock` のモダンなワークフローを採用。
  - **Python 3.14**: 将来の標準となる機能を先取りできる。
- デメリット:
  - 3.14 はプレビュー版であり、一部のライブラリが対応していない可能性がある（その場合は 3.13 にフォールバック）。

### 代替案 A (Poetry)

- 概要: 長らくデファクトだった Poetry を使う。
- 採用しなかった理由:
  - 依存解決が遅い場合がある。
  - `uv` の速度とシンプルさに魅力を感じたため。

---

## 4. 根拠（評価軸と判断）

- **Developer Experience**: 個人の開発体験を最優先し、待ち時間を減らすために `uv` を選びました。
- **Forward Compatibility**: 将来の Python の進化に追随するため、あえて最新のバージョンを指定しています。

---

## 5. 影響範囲

- **CI/CD**: GitLab CI や GitHub Actions で `uv` をセットアップする必要がある。
- **Local Dev**: 開発者は `uv` のインストールが必須。
