# ADR-0003: レポートホスティング戦略（GitLab Pages + MkDocs）

- 日付: 2025-11-22
- ステータス: 承認
- レイヤ: infrastructure
- 種別: ホスティング
- 関連コンポーネント: infrastructure.git.repo_writer

---

## 1. 背景 / コンテキスト

Kamojiros プロジェクトでは、収集・生成したレポート（Report）を人間が閲覧・検索しやすい形で公開する必要があります。
レポートの正本は Markdown ファイルとして Git リポジトリで管理することを前提としています。

- 目的・解決したいこと:
  - 生成された大量の Markdown レポートを、ブラウザで快適に閲覧できるようにしたい。
  - 検索やタグによる絞り込みを可能にしたい（初期は簡易的で良い）。
  - プライベートな環境で運用したい（外部公開しない）。

- 前提・制約:
  - レポート正本は Markdown であり、Git でバージョン管理される。
  - コストを抑えたい（個人開発）。
  - 既存の静的サイトジェネレータのエコシステムを活用したい。

---

## 2. 決定

**GitLab Pages + MkDocs** を採用し、プライベートリポジトリで運用します。
CI/CD には **自前 Runner（Local PC）** を使用し、GitLab の共有 Runner のクレジット消費を回避します。

---

## 3. 選択肢と評価

### 採用案（GitLab Pages + MkDocs + 自前 Runner）

- 概要:
  - GitLab のプライベートリポジトリで `docs/` を管理。
  - ローカル PC 上で GitLab Runner を動かし、push をトリガに MkDocs でビルド。
  - 生成物を GitLab Pages にデプロイ。
- メリット:
  - **コスト**: 自前 Runner なので計算リソースが無料。GitLab Pages も無料枠で利用可能。
  - **セキュリティ**: GitLab の認証機構（GitLab Access Control）を利用して閲覧制限が可能。
  - **エコシステム**: MkDocs (Material for MkDocs) の豊富なプラグインやテーマが利用可能。
- デメリット:
  - ローカル PC を起動していないとデプロイされない（個人運用なら許容範囲）。

### 代替案 A（GCP Cloud Run + 自前 Web アプリ）

- 概要: FastAPI + React などで自前の閲覧アプリを作り、Cloud Run にデプロイ。
- 採用しなかった理由:
  - 初期構築・運用コストが高い。
  - 認証の実装が手間（IAP は高い、自前実装は面倒）。
  - 単に Markdown を読むだけならオーバースペック。

### 代替案 B (Notion / Obsidian Publish)

- 概要: Notion API で流し込む、あるいは Obsidian Publish を使う。
- 採用しなかった理由:
  - **Git 管理** という前提と相性が悪い（Notion）。
  - コストがかかる（Obsidian Publish）。
  - エージェントからの書き込み（Git push）との親和性が低い。

---

## 4. 根拠（評価軸と判断）

- **ビジョンとの整合**: 「Markdown 正本で管理」という方針に最も合致するのが静的サイトジェネレータ（MkDocs）でした。
- **運用コスト**: 個人利用において、月額固定費がかからない構成を優先しました。
- **拡張性**: 将来的に検索機能などを強化する際も、MkDocs ならプラグインで対応したり、生成された HTML に JS を埋め込むなどのハックが容易です。

---

## 5. 影響範囲

- **ディレクトリ構成**:
  - リポジトリルートに `mkdocs.yml` を配置。
  - `docs/` 配下に Markdown を配置。
- **コンポーネント**:
  - `MarkdownReportRepository` は `docs/journal/YYYY/MM/DD/` にファイルを出力する責務を持つ。
- **運用プロセス**:
  - エージェントが `git push` すると、自動的にサイトが更新されるフローが確立される。

---

## 6. ロールアウト / 移行方針

- フェーズ1（完了）:
  - `mkdocs.yml` の作成と `docs/` ディレクトリの初期化。
  - ローカルでのビルド確認。
- フェーズ2:
  - GitLab Runner のセットアップと `.gitlab-ci.yml` の記述。
  - 自動デプロイの稼働確認。

---

## 7. オープンな論点 / フォローアップ

- **検索機能**: MkDocs 標準の検索（lunr.js）でどこまで耐えられるか。数千ファイルを超えたあたりで重くなる可能性がある。その場合は Algolia や自前検索 API への切り替えを検討する。
- **動的機能**: 「いいね」や「既読」などの動的なインタラクションをどう実現するか。静的サイトだけでは難しいので、将来的に別 API が必要になる可能性がある。
