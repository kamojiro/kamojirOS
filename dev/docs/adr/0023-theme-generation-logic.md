# ADR-0023: テーマ生成ロジック (Theme Generator)

- 日付: 2025-11-22
- ステータス: 提案中
- レイヤ: apps
- 種別: アルゴリズム
- 関連コンポーネント: apps.theme_generator

---

## 1. 背景 / コンテキスト

ユーザーの興味（Interest Profile）と最近の活動（Activity）から、次に調査すべき「テーマ」を自動生成するロジックが必要です。
単に「興味があるもの」を選ぶだけではマンネリ化し、「全く知らないもの」では興味が持てないため、バランスが重要です。

---

## 2. 決定

以下の要素を組み合わせたスコアリングアルゴリズムを提案します。

```text
Score = (w1 * Interest) + (w2 * Novelty) + (w3 * Nostalgia) + (w4 * Random)
```

- **Interest**: 現在の興味プロファイルとの合致度。
- **Novelty**: 過去のレポート（notes_index）との距離（遠いほど高い）。
- **Nostalgia**: 過去に興味を持っていたが、最近触れていないテーマ（最終更新日時が古いほど高い）。
- **Random**: 偶然性（Serendipity）の確保。

---

## 3. 選択肢と評価

### 採用案 (Weighted Scoring)

- メリット:
  - **調整可能**: 重み（w1~w4）を変えることで、「勉強モード」「散策モード」などの性格付けができる。
  - **説明可能**: 「なぜこのテーマが選ばれたか」をスコアの内訳で説明できる。
- デメリット:
  - パラメータ調整が難しい。

### 代替案 A (LLM Blackbox)

- 概要: LLM にすべてのコンテキストを投げて「いい感じに選んで」と頼む。
- 採用しなかった理由:
  - コストが高い。
  - 制御が効きにくい（ハルシネーションで架空のテーマを作るなど）。
  - コンテキスト長（トークン数）の制限。

---

## 4. 根拠（評価軸と判断）

- **Controllability**: エージェントの振る舞いを人間がチューニングできるようにするため。
- **Diversity**: 常に同じようなテーマばかり選ばないようにするため。

---

## 5. 影響範囲

- **Apps**: `ThemeGenerator` の実装。
- **Data**: `InterestSnapshot` と `notes_index` の両方を参照する必要がある。
