# ADR-0004: エージェントフレームワーク採用方針（Pydantic AI）

- 日付: 2025-11-22
- ステータス: 承認
- レイヤ: apps
- 種別: エージェント統合
- 関連コンポーネント: apps.self_observer, apps.tech_researcher

---

## 1. 背景 / コンテキスト

Kamojiros プロジェクトでは、複数の自律エージェント（SelfObserver, TechResearcher 等）を実装する予定です。
これらを実装するためのフレームワークを選定する必要があります。

- 目的・解決したいこと:
  - Python の型システム（Pydantic）と親和性が高く、堅牢なエージェントを作りたい。
  - Core ドメインや Infrastructure 層を特定のフレームワークに強く依存させたくない（汚染したくない）。
  - 将来的にはマルチエージェントオーケストレーションも視野に入れたい。

- 前提・制約:
  - 言語は Python 3.14 (preview) / 3.13。
  - すでに Pydantic を全面的に採用している。

---

## 2. 決定

**Pydantic AI** を中核フレームワークとして採用します。
ただし、複雑なマルチエージェントオーケストレーションが必要になるフェーズ（Phase 6以降）までは、**agno (旧 Phidata)** などのオーケストレーションフレームワークは導入せず、Pydantic AI 単体または素の Python で実装します。

---

## 3. 選択肢と評価

### 採用案（Pydantic AI）

- 概要:
  - 個々のエージェント（脳みそパーツ）の実装に利用。
  - 入出力や依存性注入（deps）に Pydantic モデルを使用。
- メリット:
  - **Core との親和性**: 既存の Pydantic モデルをそのまま入出力に使える。
  - **シンプルさ**: 依存性注入の仕組みが綺麗で、Repository パターンなどと組み合わせやすい。
  - **段階的導入**: 素の Python コードから一部だけエージェント化する、といった移行が容易。
- デメリット:
  - マルチエージェントの協調（会話）機能はまだ発展途上。

### 代替案 A (agno / Phidata)

- 概要: 最初から agno を全面的に採用し、Agent / Crew / Workflow を構築する。
- 採用しなかった理由:
  - "World" の概念が強く、Core/Infra 層までフレームワークの作法に合わせる必要が出てくる懸念がある。
  - 現段階ではオーケストレーションよりも「個々のエージェントの質」を高めるフェーズであるため、オーバーヘッドが大きい。

### 代替案 B (LangChain / LangGraph)

- 概要: LangChain エコシステムに乗る。
- 採用しなかった理由:
  - 抽象度が高すぎてデバッグが難しい場合がある。
  - Pydantic AI ほど Pydantic ネイティブではない（統合は進んでいるが）。

---

## 4. 根拠（評価軸と判断）

- **Core の保護**: 「Core/Infrastructure を汚さずに済むか」を最重要視しました。Pydantic AI はライブラリとして振る舞うため、ドメインロジックへの侵食が最小限で済みます。
- **開発体験**: 型安全性を重視しており、VS Code 等での補完や静的解析が効きやすい点を評価しました。
- **将来性**: 将来的に agno 等を導入する場合でも、「個々のエージェントは Pydantic AI で実装し、それを agno が外側から呼ぶ」という構成（二階建て）が可能であると判断しました。

---

## 5. 影響範囲

- **コード**:
  - `apps/` 配下の各アプリケーションで `pydantic_ai` を import して使用。
  - `core/` には `pydantic_ai` への依存を持ち込まない。
- **依存ライブラリ**:
  - `pydantic-ai` をプロジェクトに追加。

---

## 6. ロールアウト / 移行方針

- フェーズ1〜3:
  - まだエージェントフレームワークは必須ではない。素の Python + Pydantic で実装を進める。
- フェーズ3.5:
  - `apps/self_observer` の文章生成部分で初めて Pydantic AI を導入する。
- フェーズ4〜5:
  - `TechResearchAgent` などの新規エージェントを Pydantic AI で実装する。
- フェーズ6以降:
  - 複数のエージェントを協調させる必要が出てきたら、agno の導入を検討する。

---

## 7. オープンな論点 / フォローアップ

- **RAG / 検索**: Pydantic AI 自体は RAG 機能を持たない（ライブラリに任せるスタンス）。LlamaIndex や Supabase Vector 等との組み合わせ方を別途設計する必要がある。
- **プロンプト管理**: プロンプトをコードに埋め込むか、外部ファイル化するか。Pydantic AI はコード定義推奨だが、長くなると管理が辛くなる可能性がある。
